# 堆叠样例分析与双色塔顶适配

2026-10-20。已查看本目录两张示意图，并按用户确认补充需求：20 cm 塔顶是一个正方体，沿一个方向分成等厚的红、蓝两半；需要识别颜色分区及其朝向。

参考图：[图一](f7255320f1fde88b549c6fcc92c6bc86.jpg)、[图二](3ef2456c5741358072c7808e0cbd1ccd.jpg)。每张图按从左到右编号 1–6。

图中有几类原方案未充分覆盖的情况：三层而非两块；大块上放小块；层与层水平偏移或 yaw 不同；同色大块接缝很弱；双色分界是漆面变化而不是两个物体；双色塔顶可能红朝上、蓝朝上或侧放。低于塔顶的相机往往看不到真正的顶面，需要通过可见侧面的分区和已知结构求方向。

本次已加入独立 [tower 配置](../src/config/box4d_tower.json)、颜色分析模块与参考场景。原来的纯色双块配置继续可用。绿地边界和图片中的比赛计分没有纳入位姿识别：出界判断另需地面区域标定，支持关系与得分规则也不能仅由看见某种颜色决定。

## 怎样表达颜色与朝向

几何中心 XYZ、模型变换和 `yaw_u_rad` 保留。正方体几何 yaw 仍按 90° 等价，不能因为看见双色就统一改成没有歧义的 0–360° 姿态。

双色模型另外定义**从蓝半块指向红半块的单位向量**。它不随几何模型的等价面编号变化。已知物理向上方向后，可得到：

| 输出状态 | 含义 |
|---|---|
| `red_up` | 红半块在蓝半块上方，顶面为红色 |
| `blue_up` | 蓝半块在红半块上方，顶面为蓝色 |
| `sideways` | 两半横向排列，顶面为红蓝分区；另给红半块水平指向角 |
| `axis_unreferenced` | 可以求相机坐标中的颜色轴，但没有物理竖直参考，不能叫红/蓝朝上 |
| `ambiguous` | 多个颜色轴解释接近，保持未确定 |
| `insufficient_color` / `color_model_mismatch` | 颜色样本不足，或已知半块模型不符合当前观测 |

`appearance` 的主要字段：

- `faces`：每个可见面的红、蓝、未知比例，取自当前 RGB 与对齐深度支持的面内采样。
- `red_axis_camera` / `red_axis_u`：蓝→红方向，相机/竖直对齐坐标。
- `partition_plane_camera=[nx,ny,nz,d]`：分界面 `n·p+d=0`；红侧为正，蓝侧为负。该平面来自已知等半结构的模型拟合。
- `red_half_center_camera_m` / `blue_half_center_camera_m`：由模型中心与颜色轴导出的两半中心，不是额外独立深度测量。
- `top_color`：红、蓝或红蓝分区，是模型与方向的结论；不表示相机一定直接看到了顶面。
- `red_direction_yaw_u_rad`：仅侧放时给出红半块在水平面的 0–2π 指向；红/蓝朝上时为 null。
- `evidence`：`observed_color_split` 表示采到红蓝两色；`model_inferred_from_uniform_face` 表示只看到一色的完整面，借助已知半块结构推断，需单独审查。
- `remaining_symmetry_about_color_axis_rad=π/2`：绕该颜色轴仍有 90° 等价旋转，不保证获得唯一完整 6D 朝向。

在已确定的几何表面上分类颜色，不把红半块和蓝半块当成两个 10 cm 方块。HSV 阈值、最少样本数、模型一致性和歧义门限可配置。没有可靠几何位置时，不凭一片红色/蓝色输出完整双色位姿。

24 帧、46 次目标观测中定位 45 次，错误有效目标 0 次。45 次匹配的中心误差 P95 为 11.22 mm、几何 yaw 误差 P95 为 0.30°；其中 44 次同时在 15 mm / 2° 内。14 次双色目标观测均定位，并正确给出三类颜色朝向。样本是开发用的理想化合成数据，不能称为实物成功率或相机精度。

已有测试扩充至 **37 项，全部通过**：包括六种颜色轴方向、两个 yaw、红蓝反向区别、颜色不足/不符合半块结构、无竖直参考、单色完整面推断标记、三层配置和漏检的颜色统计。

速度基准使用相同 24 帧预热后重复 10 次，组合路径平均核心计算约 16.28 ms、P95 22.90 ms，预加载离线吞吐约 61.4 FPS。[完整基准](../outputs/box4d_stacking_benchmark/summary.json)。含三层和颜色的新场景不能沿用旧双块场景的约 85 FPS 结果，也尚未达到 P95 ≤16.7 ms，更不代表真实相机端到端 60 FPS。

## 运行方式与当前边界

仓库根目录：

```bash
python3 src/box4d/cli/demo.py outputs/box4d_tower_new --suite stacking --frames-per-scene 2
python3 src/box4d/cli/offline.py outputs/box4d_tower_new --config src/config/box4d_tower.json --output outputs/box4d_tower_replay_new --save-debug --video --video-fps 2
```

接相机后，沿用 [CPU 使用说明](../src/docs/box4d/BOX4D_CPU_使用说明.zh-CN.md) 的 ROS 环境、驱动和竖直标定，在实时入口增加：

```bash
python3 src/box4d/cli/live.py --config src/config/box4d_tower.json --output outputs/box4d_tower_live_new --duration 60 --display
```

没有配置 up 时不会报告物理朝上方向。合成数据自带已知 up，真实设备不会自动沿用。

新 tower 配置把上限改为 3，并将稀疏深度平面采样步长从 12 调为 8：约 1.8 m 的小件像素较少，原步长会漏掉部分完整双色件；更密采样也增加计算开销。20 cm 类别按已知双色件解释，大块只统计可见颜色；若实际同时有纯色 20 cm 件，需增加类别区分，不能直接对其套用双色结构。

待实机重点验证：光照和白平衡下的红蓝阈值；低机位的双色侧面像素数；倾斜/遮挡时的可观测性；同色偏移堆叠下层的漏检和角度抖动；三层完整流程的性能。完全遮挡的颜色与几何不作为直接观测输出，单面推断已明确标记。原有严重旋转堆叠的失败场景仍保留在 basic 测试集中，新结果不表示已解决所有遮挡。
