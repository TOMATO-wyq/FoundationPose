# CPU 方块识别逐阶段调试

此功能用于排查“正对可识别，斜着露出两个面却漏检”“识别框突然消失”。
调试窗口显示实际算法的中间结果；09 参数窗口可在不重启程序的情况下调节门限。

09 窗口的 53 个英文滑块、中文含义、单位和调整方向见 [滑块中文对照表](BOX4D_滑块中文对照表.zh-CN.md)，
其中也说明 03 窗口红色深度边缘该如何调节。

**相机驱动与下面的识别命令必须使用同一个 ROS domain。** 新启动驱动时可在另一个终端执行
`bash src/start_box4d_camera.sh --domain 86 speed`。如果现有驱动已经在默认 domain 0 运行，
把下面识别命令的 `--domain 86` 改为 `--domain 0` 即可。`no new synchronized RGB-D` 且
`Publishers=0` 时，先核对 domain 和话题路径；这时识别算法还没有获得输入图像。

## 选择平面分割后端

默认配置继续使用 NumPy 顺序 RANSAC。PCL 版本可在编译本机扩展后运行：

```bash
bash src/build_box4d_pcl.sh
bash src/box4d_ros.sh --domain 86 live \
  --config src/config/box4d_pcl_live.json --auto-up \
  --output "outputs/box4d_pcl_debug_$(date +%Y%m%d_%H%M%S)" \
  --duration 600 --debug --debug-hz 4 --debug-layout windows
```

PCL 用 `IntegralImageNormalEstimation` 计算有组织点云法线，再由
`OrganizedMultiPlaneSegmentation` 按邻接、法线和距离分割并细化平面区域；Python
只把这些区域转成面候选，并用原始深度做残差检查。PCL 的 04 窗口显示参与分割的法线，
05 窗口显示 PCL 输出区域。调 `pcl_stride` 会改变速度和细小面的保留率；1 表示不降采样，
通常更慢。PCL 后端仍会经过现有的尺寸、平整度、姿态和颜色筛选。

## 实时打开

相机驱动仍按仓库 README 启动；已有正确驱动时直接运行识别程序：

```bash
cd /home/tomato/6Dpose
bash src/box4d_ros.sh --domain 86 live \
  --config src/config/box4d_d435i_live.json --auto-up \
  --output "outputs/box4d_debug_$(date +%Y%m%d_%H%M%S)" \
  --duration 600 --display --display-smoothed \
  --debug --debug-hz 4 --debug-layout windows
```

默认打开八个阶段窗口和一个 09 参数窗口。窗口太多时将 `--debug-layout windows` 改为
`--debug-layout grid`，在一个窗口显示八个阶段；参数窗口仍单独显示。使用 `--debug` 无须同时开启
`--display`；后者只控制原有最终三维框窗口。

09 参数窗口现在分为 **8 页，每页最多 7 项**，每个滑块直接显示中文与英文名称。
点击底部的 **上一页／下一页** 按钮，或者在调试窗口按 **[ / ]** 切换上一页／下一页；切页保留其他页的修改，
无需向下滚动。页面依次为：输入深度与 Canny、深度边缘与颜色、颜色模型与平面验收、PCL 法线与平面、候选与尺寸验收、位姿检查与重检测、跟踪与特征点、光流与补点。
旧进程需要先按 S 保存，再退出并重新运行原命令，才能使用分页窗口。

09 窗口中的滑块实时改变当前识别配置。按 **S** 会把全部页的完整配置写回启动时的 `--config` 文件，
并另存为本次输出目录下的 `tuned_config.json`；同时保存当前调试快照、RGB-D 和测量数据。
下一次可直接用保存后的配置启动。深度边缘、颜色提案、PCL 法线/平面、面尺寸/平整度/姿态、
跟踪门限都在滑块中；HSV 色相范围、颜色模型开关、对象尺寸列表等复合选项继续在 JSON 中编辑。
滑块变更会在后续处理帧生效；异步全图检测可能仍显示刚完成的旧检测帧，顶部的 DETECT 帧号和年龄可用于确认。

`--debug-hz` 仅限制诊断绘图提交频率。记录中间数据、计算法向量和绘图会增加计算与内存开销，
调试运行的 FPS 不能当作关闭调试后的性能；`processing_ms` 不包含主线程额外的调试绘图时间。

在任一调试窗口、09 参数窗口或最终预览窗口按键：

| 按键 | 用途 |
|---|---|
| 空格 | 冻结/恢复调试画面；冻结时标注 `FROZEN`，识别仍继续运行 |
| N / P | 查看下一个/上一个候选面，详细窗口中的 F 编号对应候选窗口 |
| L | 切换整图检测与局部补搜 ROI；每个视图显示实际来源 ROI |
| [ / ] | 在调试或 09 窗口切换参数页；最终预览窗口不处理此快捷键 |
| S | 保存当前配置，并保存最近提交的整组调试画面、原始 RGB-D 和数值 |
| Q / Esc | 结束本次识别；关闭任一调试窗口也结束本次识别 |

## 八个阶段窗口怎么看

以下理想状态主要针对方块所在区域。背景有边缘、平面或被拒绝的候选很正常；每个中间窗口都很干净，也不保证最终位姿一定通过。

流程是：**彩色图＋对齐深度＋相机内参 → 颜色／边缘／三维平面多路提出候选 → 几何、颜色和场景验收 → 当前帧跟踪复核 → 最终三维框**。
02、03、05 是多路证据，07 是对 06 中所选候选的详细检查，并非每个窗口都代表一个独立的串行关卡。

| 窗口 | 使用的特征、提供的数据 | 方块区域的理想状态 | 优先排查的异常 |
|---|---|---|---|
| **01 Input + aligned depth：原始输入** | 左边彩色图，右边同帧对齐深度；深度配合内参把像素转为三维点，供拟合平面、量尺寸和验证位姿 | RGB 清楚；目标面有较完整、稳定的深度；深度轮廓与 RGB 轮廓基本对齐。同一平面颜色可平滑变化，倾斜面不必同色 | 目标内部大片黑洞、彩色与深度轮廓明显错位、深度大幅跳变。黑色表示无效或超出所设距离范围 |
| **02 Color proposals：颜色候选** | HSV 色相、饱和度、亮度；红蓝像素用于候选、搜索优先级、最终颜色覆盖验收及双色件颜色方向判断 | 实际红色、蓝色表面大体被正确标出；区域随时间稳定。白色图案、反光等部分允许未分类，不要求整个面全部染色 | 明显红蓝表面大块消失、持续被误分颜色、候选与背景粘连。颜色掩膜影响候选，但颜色本身不直接给出三维距离 |
| **03 RGB + depth edges：图像与深度边缘** | 白色为灰度／亮度 Canny 边缘；红色为两个相邻有效深度的差值超过门限。合并后用于提取候选四边形、细化边线和评估边界吻合程度 | 目标轮廓附近有稳定可用的白色或红色边缘；平整面内部少有乱跳的红碎点。表面图案有白线可以接受 | 真正轮廓长期缺失，或面内部出现大量深度碎边。公共棱可以深度连续，不要求方块轮廓完整画成红色；背景红点多不能单独判坏 |
| **04 Local normals：局部法线** | 用邻域三维点估计局部表面朝向，再把方向编码为颜色。PCL 显示参与分割的实际法线；NumPy 显示三维差分诊断法线，后者不参与 NumPy 分割 | 静止时，同一平面内部方向大体一致、颜色相近；不同朝向的面有相应区别。边缘和缺深度处允许黑色或不稳定 | 面内部大片随机翻色、有效区域太少。平行但距离不同的面可以同色，不能靠这张图判断是否共面 |
| **05 Plane regions：三维平面区域** | NumPy 顺序 RANSAC，或 PCL 的局部法线、有组织邻接和多平面分割；输出平面法线、位置、RMS、支持率及区域掩膜，继续生成面候选 | 可见面的主要部分被稳定保留，少碎裂、少混入背景；同一方块相邻两面能分开。区域可以不规则，不必已经是完美矩形 | 只剩小片云朵、大片缺失、一个区域跨过两个不同朝向的面。颜色只是编号，每次检测可能换色，应比较区域位置与形状 |
| **06 Face candidates：候选面** | 由边缘轮廓、颜色区域、三维平面及堆叠／遮挡模型提出四边形，并显示几何验收状态 | 目标上至少出现吻合可见面、尺寸合理的候选，尽量不跨公共棱；正确候选能通过几何验收。允许有一些背景候选被拒绝 | 目标上没有候选、正确轮廓经常变成红框、候选跨两个面或明显框到背景。绿色是几何通过，后面仍有颜色与场景筛选 |
| **07 Face validation：候选验收细节** | 所选候选内部的深度采样、点到平面距离、三维边长、PnP／深度求解的重投影、深度、法向和竖直误差；用于接受或拒绝该候选的位姿解 | 采样点多数贴合该面，实测数据稳定；RMS／误差低于各自上限、支持率／覆盖率高于下限，尽量留有余量；尺寸与已知模型相符 | 指标反复贴着门限跳动，或某一项持续失败。黄色框仅表示选中了该候选；绿点是平面内点、红点是超出平面距离门限，最终应看 status 与 Reason |
| **08 Current tracking：当前跟踪** | Harris 图像角点、前后向 LK 光流、运动一致性，以及当前深度、边缘、颜色复核；输出当前帧的位姿与失败原因 | 绿点分散在可用面上，不挤在一条边或很小的图案里；点随物体运动、不漂向背景；输出数量与位姿稳定，少有失败 | 特征点很少或集中、向背景漂移、静止也反复丢框。此处绿点是当前成功测量的图像特征，和 07 的深度采样点不同 |

检测与当前帧跟踪现共用 `box4d/edges.py`：灰度 Canny、HSV 明度 V 的 Canny、
相邻有效深度跳变三者合并，并使用相同的深度范围和 ROI。03 显示的是检测源帧，
08 使用相同算法检查当前帧；两帧内容可以不同，但不会再漏掉一种边缘来源。

补充判断规则：

- **01 深度伪彩色**只表示相机前后方向的深度，不表示好坏，也不能单独区分平面朝向。
- **04 法线颜色**表示方向；**05 区域颜色**表示编号。05 换颜色不能直接当作平面不稳定。
- **05 中同一方块的相邻面**理论上法线夹角约 90°；两块方块的平行面接近 0°是正常的。底部 P0/P1 是前两个报告平面，可能包含背景，只有先确认它们属于目标面时才适用这个判断。
- 两块方块若正面恰好共面，可以共享平面区域；后续还需用边界、尺寸或颜色等证据区分物体，平面数量不等于方块数量。
- **07 的 RMS 通常针对平面内点计算**，少数点贴得很好也可能 RMS 很低，必须同时看内点支持率和有效深度覆盖率。
- **08 当前主要选择一个可用面跟踪**，并未实现强制在所有可见面均匀取点。理想的分布要求针对当前被选的面。

**09 Tuning** 是参数控制面板，不是新的识别证据。每次改一项，观察对应窗口和最终框，按 S 保存全部页的设置。
**Box4D CPU** 是最终预览：三维框应贴合物体，静止时少跳动，运动时能及时跟随，位置和朝向与实际一致。
显示平滑只影响已有结果的展示，不能证明位姿准确，也不能恢复被拒绝帧的输出。

后台检测使用较早的图像，因此 01–07 明确标注 `DETECT frame=... age=...ms`，
画面和数据都属于该检测帧。08 标注 `CURRENT frame=...`。未完成首次检测时显示等待；
等待/冻结的中间结果不代表当前帧通过了校验。局部补搜可用 L 单独查看。

## 面很准，为什么最终框还会消失

07 的黄色轮廓表示当前选中的候选面，**无论它是否通过全部检查都会画出来**。
绿点表示采样点接近平面，红点表示超出平面距离门限；这些只说明点到平面的关系，
不代表尺寸、位姿、颜色或当前帧跟踪已经通过。先看该窗口底部的 `status`、`Reason` 和实测值。

在实时异步模式中，后台检测完成后，程序还要在检测帧选出分散的图像特征点，再跟到当前帧，
重新检查当前深度、位姿、边界和颜色，才会输出方块。即使后台已经找到正确方块，
也可能在这一步失败；01–07 的检测画面还会保留到下一次后台检测完成。

目前任何一次当前帧验收失败，都会停止输出该方块的当帧位姿，因此静止目标也可能出现闪框。
`Track gap ms` 只保留短暂恢复用的图像和关联状态，并不会让消失的框继续显示。
`--display-smoothed` 只平滑已经成功输出的结果，也不会补画失败帧。

最终预览的 `POSE REJECTED` 表示存在当前校验拒绝；`SEARCHING` 表示没有当前可用观测。
08 的 `New detector result` 是本帧刚收到的后台目标数，`--` 表示本帧没有新的后台结果；
`current RGB-D passed` 是其中通过当前帧复核的数量。这两个数字不能混为一谈。
`temporal.*failure_details[].pose_trials` 记录每个位姿候选的实测误差及失败项；
汇总原因中的“边界、深度”可能分别来自不同候选，不表示同一个解同时违反了这两项。

启用 `color_line_fallback` 后，会对尚未检测到的配置尺寸补充线交点候选。
例如检测到 35 cm 方块后，仍能为缺失的 20 cm 方块执行补救；补充候选仍需通过原有全部校验。

优先看 **08 的 Current failures**，再按失败项目调整；不要因为框消失就同时放宽所有平面参数：

| 失败原因 | 中文含义 | 对应参数／检查 |
|---|---|---|
| `feature_reprojection` | 由跟踪点求出的位姿投影与当前图像不够吻合 | 第 6 页重投影门限；也要看特征点是否集中或漂移，放宽只会接受更大的错位 |
| `current_boundary_support` | 预测轮廓附近没有足够的实测边缘 | 第 5 页边缘支持率，结合 03 看真实边界是否保留；还存在至少两条边支持率超过 40% 的固定条件 |
| `current_depth_residual` | 当前深度与位姿所表示的面不一致 | 第 6 页位姿深度残差，并检查候选有没有跨面或混入背景 |
| `tracked region no longer has target colors` | 当前投影区域的红蓝颜色覆盖不足 | 第 2 页颜色覆盖率，结合 02 检查白色图案、暗部、反光或投影偏移 |
| `tracked feature coverage too narrow` | 特征点虽存在，但挤在面的一小块 | 第 7 页特征点覆盖率、初始特征点上限；降低覆盖门限会接受更差的几何分布 |
| `detected face lacks usable tracking features` | 后台检测找到了方块，但未能初始化可用跟踪 | 当前会逐个尝试可见面，并只选一个可用面；可能是特征点不足、覆盖不足，或初始化的平面／深度检查失败 |

08 只显示提交调试画面时那一帧的原因，4 Hz 显示可能错过短暂失败。
本次输出目录的 `poses.jsonl` 会逐帧记录 `temporal.tracking_failures` 和
`temporal.detector_seed_failures`；最终定位应结合该记录，而不是只凭一张截图。
`tracking_failure_details` 还会记录是 20 cm 还是 35 cm 方块失败，以及光流点数、
特征覆盖率、平面支持率和对应门限。08 下方会显示其中的关键数值。

`track_feature_method` 可在 JSON 中选 `adaptive`（默认）、`harris` 或 `shi_tomasi`。
`adaptive` 优先保留可用的 Harris 角点；Harris 点数或覆盖不足时再尝试 Shi–Tomasi，
避免低纹理面一直无法补点。选出的点仍需通过后续光流、几何、深度、边界和颜色校验。

第 8 页新增 `Track depth inset % / 跟踪深度内缩 %`，对应
`track_depth_inset_fraction`，默认 0.10。跟踪先检查完整面内部的原始深度；只有平面
支持率或 RMS 不通过时，才尝试每边向内缩 10% 后重新采样。完整面的深度覆盖检查仍须通过，
内缩后也使用相同的 65% 平面支持率和 6 mm RMS 门限，整面图像边界检查照常进行。
它能减少模型轮廓略超出真实布面时混入背景的影响；不能恢复没有深度的数据。
设为 0 可关闭这项恢复。成功位姿的 `metrics.depth_sampling_inset_fraction` 记录实际是否用到内缩。

按 S 后写入本次输出目录的 `debug/snapshot_编号_frame_帧号/`：

- `01.png` 至 `08.png`：所选视图的完整画面。
- `measurements.json`：相机标定、阈值、每个平面、每个候选面、全部求解尝试及拒绝原因；同时保留检测帧与当前帧信息。
- `current_rgbd.npz`、`detection_rgbd.npz`：两者各自的 RGB 和米制深度；检测尚未完成时没有后者。

S 保存配置后，图片和 RGB-D 压缩改在后台写盘；终端先打印 `queued`，写完后打印
`saved`。最多同时保留两组待保存数据；若显示 `busy`，本次配置已保存，快照需等写盘
结束后再按 S。正常退出会等待已经接收的快照写完，避免保存操作打断图像跟踪。

## 判断双面失败卡在哪里

1. 04 已出现两种稳定方向、05 却只保留一个目标面：优先查逐次 RANSAC、小面采样点数、平面搜索预算，以及形态学操作是否删除窄面。
2. 05 有两个面，06 的四边形却横跨公共棱：优先查轮廓提取和候选面构造。
3. 07 的 RMS 不高，但支持率不足：可能是一个候选混入两个面，不能只靠放宽 RMS 修复。
4. 07 几何通过，08 却失效：继续查看特征点分布、当前深度或后台重捕获失败原因，以及颜色/场景选择。

当前普通面的主要门限：平面内点距离 8 mm，内点 RMS ≤6 mm，内点支持率 ≥65%，
有效深度覆盖率 ≥45%，尺寸最大相对误差 ≤12%，深度残差 ≤12 mm，法向误差 ≤15°，
竖直模型倾角 ≤12°。这些是经验固定门限，并非已经标定的传感器置信区间。
遮挡恢复使用更严格的 75% 支持率及额外可见性条件。
PnP 重投影门限按配置参考宽度换算，窗口显示实际使用的像素门限。

全场景平面的 `support` 是对该次搜索样本的支持率；普通面校验的 `plane_support`
是对该候选面内部样本的支持率，二者的分母不同，不能把全场景支持率直接套入 65% 门限。

NumPy 后端使用 RANSAC + 内点协方差最小特征向量细化；PCL 后端使用有组织点云法线和多平面分割。
两种后端都按三维点到平面的距离判断，不能只看深度图上的 Z 差来判断面数。PCL 是可选实验后端，
是否更适合当前相机与场景要结合 `comparison.json` 和保存的逐阶段画面判断。

## 无相机时回放

```bash
python3 src/box4d/cli/offline.py 录制目录 \
  --config src/config/box4d_d435i_live.json \
  --up-camera UX UY UZ \
  --output outputs/box4d_stage_replay_new --max-frames 10 --save-stages
```

`UX UY UZ` 替换为该段录制时的竖直参考；数据自带正确 UP 时可省略。
每帧在 `stages/000000/` 等目录保存上述八张图、RGB-D 和 JSON。
`--save-stages` 会大量写盘；原有 `--save-debug` 仍仅保存最终叠图和边缘图。
