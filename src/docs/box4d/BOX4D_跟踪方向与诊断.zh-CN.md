# 跟踪方向连续性、补点纠偏与日志对照

这轮修改针对近正对时姿态候选来回切换，以及补点可能延续旧方向偏差的问题。方向窗口只帮助选择当前帧已经通过几何验收的候选，不插值输出、不预测缺失位姿，也不固定 pitch/roll。YOLO 仍提供实例分割与 ROI，最终位姿继续使用当前图像和深度。

## 参数与第 12 页滑杆

在 09 调参窗口按 **[ / ]** 切到第 12 页“方向连续性与补点纠偏”。按 **S** 保存整个配置，而不只是当前这一页。文件字段使用下表的物理单位；滑杆按显示单位换算。

| 中文滑杆 | config 字段 | 默认值 | 滑杆默认显示 | 调整含义 |
|---|---|---:|---:|---|
| 方向窗口时间 ms | `track_direction_window_tau_s` | 0.20 秒 | 200 | 越大，角速度趋势记得越久；越小，趋势更快跟随当前变化。它不是对最终角度做 200 ms 平滑 |
| 方向先验权重 ×0.001/deg | `track_direction_prior_per_deg` | 0.02/度 | 20 | 候选方向偏离预测 1° 增加多少代价。调大更偏向连续分支；调小更依赖当前观测；0 关闭方向先验 |
| 反向逃生代价优势 ×0.01 | `track_direction_escape_margin` | 0.15 | 15 | 偏离趋势的候选需要持续有多少观测代价优势才能累计逃生证据；该值也作为补点纠偏的证据优势要求。调大更谨慎，调小更容易纠偏或转向 |
| 反向逃生连续帧数 | `track_direction_escape_frames` | 3 | 3 | 持续支持同一偏移方向、且优势达标多少帧后允许观测接管。优势足够强、唯一有效候选等情况可立即接管，不必等满 3 帧 |
| 补点最大旋转 deg | `track_reseed_max_rotation_deg` | 15° | 15 | 实测平面提出的补点纠偏相对当前姿态超过此值时，拒绝这次补点。它不限制正常跟踪时方块能够转多少度 |

`track_joint_on_ambiguity` 默认 `true`，在配置文件中控制。启用后，满足以下两个条件时，普通 PnP 即使尚有候选通过，也会额外尝试联合解：

1. 观测代价最低的普通候选接近正对，`view_cos > 0.95`。
2. 该候选相对上一状态的完整旋转步长大于 5°。

联合解仍必须通过原有图像、深度、法线、位置和边界验收，再与其他候选一起比较。普通候选全被拒绝时，原来的 joint 兜底仍然运行，与这个开关无关。它不是每帧都强制以深度面替代图像解。

将 `track_direction_prior_per_deg` 设为 0，只关闭方向先验及其趋势影响。它不会回滚按需 joint、联合目标归一化、补点纠偏、诊断修复等其他改动。单独比较 joint 的近正对触发，可切换 `track_joint_on_ambiguity`。

## 方向窗口怎样工作

每条轨迹保存独立的三维角速度趋势，用实际帧间时间预测下一帧旋转增量。比较的是完整旋转，不是 Euler pitch 的正负号。静止和微小噪声会使趋势逐渐衰减至零；疑似孤立跳变不会轻易写成下一帧的运动趋势。

每个候选的最终分数包含当前图像、深度、法线、原有 yaw 项和方向先验。两种姿态都贴合观测时，符合近期趋势的候选更容易胜出。当前观测足以克服先验时立即响应；较弱但持续、同方向的优势可累计逃生证据。只有一个候选可行，或所有候选都与预测冲突时，直接交还当前观测，避免为了连续性制造额外丢帧。

新获取、换面和较长断档会重置方向窗口；正常补点延续轨迹窗口。窗口属于各自状态，复制后不共享可变数组。没有验收通过的候选时不输出旧姿态，窗口也不会补出一个“预测框”。

## 补点怎样纠偏

补点先由当前深度平面提出纠偏姿态。纠偏转角超过配置上限时拒绝这次补点；其余情况用同一批现有模型点、当前图像点和深度内点，分别验收纠偏姿态与当前跟踪姿态。纠偏候选未通过时，仍可使用通过验收的当前姿态补点；两个候选都未通过才拒绝这次补点。比较时加入方向软代价，并给纠偏候选附加所需的证据优势。仅有微小观测改善时，优先保留当前姿态，避免每次补点都把法线噪声带进来。

选择纠偏后，发布位姿、内部对象、面几何和新特征模型一起更新，避免“这一帧画旧框、下一帧使用新模型”。如果拒绝补点，当前帧 `_advance` 已通过验收的结果仍可发布和继续跟踪；不会因此发布更早帧的旧位姿。

joint 的图像残差按约 1 px 噪声标准化，深度残差按实测平面 RMS 和至少 2 mm 的噪声尺度标准化。两组在稳健损失后分别按点数归一化，增加图像或深度样本不会仅因数量增加就放大整组权重。所有当前深度内点都参与，求解保留真实三维转动；最终仍使用原有几何门槛。

## 无 debug 时也能查看的日志

普通运行的 `poses.jsonl` 保存轻量数值记录。每个候选在参数和几何检查之前先建立 trial，非有限参数、相机后方、背面、掠射、无效投影等早退也写入失败阶段和原因。跟踪求解器本身异常或根本没返回候选，记录在 `solver_attempts`；完整检测阶段的同类错误以 `stage="solver"` 的 trial 记录。它们均不伪造一个已经求出的位姿。

| 字段 | 该怎样理解 |
|---|---|
| `temporal.tracking_checks` | 已有轨迹推进至当前帧的完整检查 |
| `temporal.detector_seed_checks` | 异步检测从源帧初始化，再推进至当前帧的检查 |
| `temporal.reseed_checks` | 当前帧补点时，实测平面纠偏与当前姿态的比较 |
| `pose_trials[].accepted` | 候选通过原几何验收，尚不代表最终发布 |
| `pose_trials[].selected` | 此检查组实际选中的候选；最终对象通过 `metrics.tracking_check_group/index` 指向它 |
| `pose_trials[].stage / failed_checks / reason` | 检查进行到哪里、因为什么失败 |
| `pose_trials[].cost_components` | 图像、深度、法线、yaw、方向等代价分项；补点还包含所需证据优势 |
| `direction_prior_deg / direction_prior_cost / applied_direction_cost` | 相对趋势的偏离，以及原始与实际应用的方向惩罚；逃生或唯一候选等情况可撤去惩罚 |
| `measured_plane_normal_step_deg` | 当前实测平面相对上次成功测量的法线变化 |
| `pose_rotation_step_deg / pose_normal_step_deg` | 实际姿态完整旋转、所跟踪面法线的变化；与上一项分开看，判断是观测面在漂还是求解在跳 |
| `detector_diagnostics.objects / detection_checks` | 检测源帧的物体与所有实际尝试的面/求解候选；同步检测也保存源快照 |
| `detector_seed_stamp_ns` | 本帧接收新检测种子的事件，下帧清除；不能当作持续确认标记 |
| `origin_detection_stamp_ns` | 此轨迹持续保留的检测来源时刻 |
| `detector_match_action` | `confirm` 仅确认目标身份；`face_switch` 表示接管了新检测的面几何 |

`trial_index` 不是跨帧唯一 ID。跟踪 trial 的完整定位包含：**运行目录 + 当前 `stamp_ns` + `tracking_check_group` + `tracking_check_index` + `trial_index`**。角度变化与上一状态的成功观测比较，失败后恢复时可能跨过多帧，要连同时间差阅读。

检测候选定位使用运行目录、检测源 `stamp_ns`、`face_index`、`trial_index`。YOLO 多 ROI 与普通局部搜索合并后会重排 `face_index`，同步更新物体与面的 `detection_check_index / detection_trial_index`；源局部编号和来源上下文仍保留，坐标不平移。最终掩膜过滤或场景压制之后，聚合检测记录的 `selected` 会重新计算。

`detector_diagnostics.detection_checks[].selected_object_indices` 指向同一快照的 `detector_diagnostics.objects`，不指向当前跟踪输出。快照在时间跟踪合并前深拷贝，保留的是当时检测阶段的选择；不代表当前跟踪必然接管了那个姿态。`local_searches[].detection_checks` 另外保留子程序的局部选择，局部 `selected` 也不能当作聚合检测选择。

源帧时间、标定和年龄见 `detector_diagnostics.source_frame / current_frame / age_ms`；旧检测像素不会被包装为当前帧检测。异步快照深拷贝对象、候选和局部报告。逐点采样、逐点残差等大数组仍只在 debug 快照中保存，不常驻普通 JSONL。

## 验证边界

原几何门槛、CPU 推理、后台单槽调度及 C++ 内核接口保持不变，C++ API 仍为 4。方向选择与当前帧联合目标使用 Python/OpenCV/SciPy，已有 C++ 几何仍照常启用，不要求改用 CUDA。

之前分析的静止翻转记录 `box4d_cpp_20261030_231004` 没有原始 RGB-D，不能逐帧重新执行检测和求解。已有录制片段可以检查候选选择、正常运动、补点、输出覆盖率和 CPU 耗时，但不能代替对那次静止现场的复测，也不能保证光照、深度缺失或特征不足引起的问题全部消失。
